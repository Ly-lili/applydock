# 求职投递悬浮面板 PRD

> 版本：v0.1（需求草案）<br>
> 日期：2026-09-30<br>
> 产品形态：Windows 桌面应用<br>
> 技术方向：Electron + React + TypeScript<br>
> 状态：待确认

## 1. 产品概述

求职者在招聘网站、企业招聘系统或其他应用中填写投递表单时，经常要反复查找并复制姓名、联系方式、经历、项目介绍及常见问题的答案。本产品提供一个可置顶、可拖动的桌面悬浮面板，让用户在填写表单的同时查看资料，并一键复制所需内容。

首版以“用户选择内容 → 复制 → 回到目标表单粘贴”为核心流程。面板由用户主动管理内容，不依赖特定招聘网站。

## 2. 目标与衡量方式

### 2.1 产品目标

1. 减少用户在简历文件、笔记和招聘表单之间切换的次数。
2. 让常用投递信息保持可见，并能在两次操作内完成复制。
3. 让用户自由调整面板位置，避免遮挡当前正在填写的区域。
4. 将个人资料保存在本机，首版无需注册或登录。

### 2.2 首版验收指标

| 指标 | 验收口径 |
| --- | --- |
| 获取常用字段 | 打开面板后，用户可以通过滚动或搜索找到字段，并点击一次复制 |
| 复制反馈 | 点击复制后显示成功提示；粘贴结果与保存内容一致，保留换行 |
| 跨应用可用 | 面板在普通浏览器窗口和其他常规桌面窗口前保持可见 |
| 内容持久化 | 保存内容后退出并重新启动，字段、分类及排序仍然存在 |
| 位置持久化 | 重新启动后恢复上次位置；屏幕配置变化时面板仍可见 |

## 3. 目标用户与使用场景

**目标用户：** 正在集中投递岗位、需要反复填写相似资料的求职者。

**典型场景：**

1. 用户打开招聘网站的申请表，同时呼出悬浮面板。
2. 用户查看“联系方式”分类，点击“邮箱”右侧的复制按钮，再粘贴到表单。
3. 用户遇到“介绍一个项目”的文本框，搜索项目名称并复制预先整理好的回答。
4. 面板挡住输入框时，用户拖动面板或收起为小条，继续填写。

## 4. 首版范围

### 4.1 P0：必须实现

| 模块 | 需求 |
| --- | --- |
| 悬浮窗口 | 独立小窗口、默认置顶、可拖动、可收起与展开、可关闭；窗口大小可调整 |
| 显示控制 | 可通过托盘图标和全局快捷键显示或隐藏面板；关闭窗口时可选择隐藏到托盘 |
| 内容管理 | 面板内提供“新建字段”入口；用户可输入标题、选择或新建分类、输入多行正文；支持编辑和删除已有字段 |
| 内容查找 | 按标题和正文搜索；按分类浏览；长内容可展开查看 |
| 一键复制 | 每个字段均有复制按钮；复制完整正文；复制成功后给出明确反馈 |
| 本地保存 | 字段点击“保存”后立即写入本地；分类、排序、窗口位置及展开状态在变更后自动保存 |
| 初始体验 | 首次打开时展示示例分类和空白字段提示，用户可直接编辑或删除 |

建议的初始分类：基本信息、教育经历、工作经历、项目经历、作品与链接、常见问答。这些仅是起点，用户可以自行修改。

### 4.2 P1：首版稳定后考虑

- 多套资料方案，例如“产品岗位版”“开发岗位版”。
- 字段置顶和最近复制记录。
- 从文本、Markdown 或 JSON 导入内容，以及导出备份。
- 可配置快捷键、面板透明度和主题。
- 为同一问题保存多个答案版本。

### 4.3 暂不纳入首版

- 自动识别招聘网站表单并代替用户填写。
- 自动投递岗位或提交申请。
- 云端同步、账号系统及团队共享。
- 使用 AI 自动生成或修改投递内容。

## 5. 核心交互

### 5.1 面板结构

```text
┌─────────────────────────────────────┐
│ 拖动区  投递资料       收起  置顶  隐藏 │
├─────────────────────────────────────┤
│ 搜索资料…                  [+ 新建字段] │
│ 基本信息  经历  项目  常见问答  …       │
├─────────────────────────────────────┤
│ 邮箱                     [复制] [编辑] │
│ example@email.com                   │
│                                     │
│ 项目介绍                 [复制] [编辑] │
│ 这段内容可以展开查看…                │
└─────────────────────────────────────┘
```

- 面板默认宽度建议为 360 px，用户可以调整大小；具体尺寸以原型和实际使用测试为准。
- 拖动仅发生在顶部拖动区；复制、编辑、搜索和滚动区域保持正常鼠标交互。
- 收起后保留一条可拖动的小条，可一键展开。
- “隐藏”让面板从屏幕消失，可通过托盘或快捷键重新显示；“关闭应用”从托盘菜单执行。

### 5.2 主要流程

**首次使用：** 启动应用 → 查看示例分类 → 点击“新建字段” → 输入内容并保存 → 开始投递。

**复制内容：** 呼出面板 → 搜索或选择分类 → 点击“复制” → 看到“已复制”提示 → 切回目标输入框粘贴。

**编辑内容：** 点击字段的“编辑” → 在面板内打开编辑页 → 修改内容 → 点击“保存”并返回列表；点击“取消”则放弃本次修改。

### 5.3 字段输入与编辑页

点击列表顶部的“新建字段”或某个字段的“编辑”，在**同一个悬浮窗口**中切换到编辑页。用户不需要打开外部文件或另一个应用。编辑页包含：

| 输入项 | 控件与规则 | 示例 |
| --- | --- | --- |
| 字段标题 | 单行输入，必填；用于列表和搜索结果展示 | 自我介绍、邮箱、项目 A 介绍 |
| 所属分类 | 下拉选择已有分类，并提供“新建分类”入口；默认选中当前分类 | 基本信息、项目经历 |
| 字段内容 | 多行文本框，必填；保留用户输入的换行和标点 | 可直接粘贴到申请表的完整回答 |

```text
┌─────────────────────────────────────┐
│ ← 返回          新建字段             │
├─────────────────────────────────────┤
│ 标题 *                              │
│ [项目 A 介绍______________________]   │
│ 分类                                │
│ [项目经历              ▾] [+ 新分类] │
│ 内容 *                              │
│ ┌─────────────────────────────────┐ │
│ │ 在这里输入或粘贴需要投递的内容…  │ │
│ │ 支持多行文本                    │ │
│ └─────────────────────────────────┘ │
│                       [取消] [保存] │
└─────────────────────────────────────┘
```

保存成功后立即返回字段列表，并显示新建或修改后的内容。点击“取消”或“返回”时，若存在未保存修改，先提示用户选择“继续编辑”或“放弃修改”。首次使用的空状态也提供醒目的“新建字段”按钮。

## 6. 功能规则与异常处理

1. 新建或编辑字段时，标题和正文不能为空；不满足条件时禁用保存并标出缺失项。已有空正文不可复制，复制按钮置灰。
2. 支持多行文本、中文标点和链接，复制时保持原始内容与换行。
3. 删除字段需要二次确认，防止误删长篇回答。
4. 搜索无结果时显示空状态，并提供“新建字段”入口。
5. 全局快捷键与其他程序冲突时，应用仍可通过托盘打开，并提示修改快捷键。
6. 面板置顶状态可由用户切换；状态改变后立即在界面上体现。
7. 多显示器连接或断开后，若上次窗口坐标超出当前屏幕范围，应将面板移回可见区域。
8. 本地保存失败时应明确提示，停留在编辑页并保留当前输入内容供用户重试。

## 7. 数据与隐私

字段数据建议包含：唯一 ID、标题、正文、分类 ID、排序值、创建时间、更新时间。应用设置单独保存，包括窗口位置、尺寸、置顶状态及快捷键。

首版数据只保存在本机，不上传服务器。界面应提醒用户避免保存登录密码、验证码等一次性或高敏感信息。后续如加入云同步，需要单独设计授权、加密和数据删除机制。

## 8. 技术实现建议

| 层 | 建议方案 | 职责 |
| --- | --- | --- |
| 桌面容器 | Electron | 创建窗口、置顶、托盘、全局快捷键、系统剪贴板 |
| 界面 | React + TypeScript | 面板列表、搜索、编辑与交互反馈 |
| 本地存储 | SQLite | 存储字段、分类和设置；首版数据量虽小，但便于后续搜索与多方案扩展 |
| 桌面接口 | Electron preload + IPC | 向界面暴露受限的复制、窗口和存储操作 |

建议启用 Electron 的 `contextIsolation`，通过 preload 暴露有限接口；不要让页面直接获得完整 Node.js 权限。界面只加载应用自带资源，不需要访问招聘网站内容。

## 10. 待确认事项

这些问题不阻碍原型开发，但会影响首版细节：

1. 首版是否只面向 Windows，还是同时需要 macOS？
2. 用户是否需要保存多份不同岗位方向的资料，还是先使用一套资料？
3. 关闭面板时，是默认隐藏到托盘，还是直接退出应用？
4. 是否需要导入现有简历或笔记，减少第一次录入的工作量？
